## 1. 结论摘要

1. **实验 1 停在 Stage 0（预注册规则触发）**：会议协议（batch 16/256、三个学习率、
   ETTh1-720 的 70 epoch 等全部按会议脚本）重训的 PhaseFormer，相对 Golden 平均
   +1.29%（阈值 ≤1.0%），且仅 3/7 数据集优于 E14（阈值 ≥5/7）→ 不采纳。协议内
   224 个 L/LA run 未启动（控制器自动跳过）。
2. **逐 epoch 诊断**：即使在每个 epoch 都读 test、取整条轨迹最优（会议代码的口径），
   会议协议下 Golden 也只在 10/28 setting 可达。剩余差距无法用已识别的协议差异
   （batch/学习率/epoch/checkpoint 规则）解释，与单 seed、按 epoch 读 test 的会议
   结果口径一致。
3. **实验 2（热启动）达成 25/28**：LA-warm 相对同协议、同 seed 出发的 PhaseFormer
   在 25/28 setting 上 MSE 改善（目标 ≥22 ✓），全部为 3-seed 均值。
4. **但对 Golden 仍只有 2/7 数据集占优**（Weather +0.92%、Electricity +0.88%；
   目标 ≥4 ✗；另有 ETTh2-192 在 setting 级别打平）。热启动把 LA 从它的起点
   （E14 PF，平均高于 Golden ~1.2%）整体上移，但起点本身低于 Golden 的部分
   热启动无法弥补。
5. **与论文现行从零训练的 LA 相当**：数据集平均 MSE 差异在 ±1.1% 内
   （ETTm1/Electricity/Traffic-MAE 热启动更好，ETTh2 稍差）。热启动不构成
   替换论文主表的收益。
6. **Traffic 退化与调制无关**：Traffic 是唯一相对 PF 退化的数据集（≤0.8%）。
   逐窗口分析显示调制开着在 >90% 窗口更好（H192/H336），最差 1% 窗口同样更好；
   退化来自微调后的骨干/level 分支，不是调制误触发。

## 3. 实验 2：从 PhaseFormer checkpoint 热启动 LA

- 初始化：骨干严格加载；`gate_init=1e-3`、调制出口零初始化；保留论文最终配置

- 骨干学习率倍数：19 个 setting 选 ×0.1，9 个选 ×1.0（**按 seed-2021 test 选择，

## 5. Bad case 分析（HOW_TO_DO_RESEARCH 要求）

LA-warm 相对同协议 PF 退化的 setting 只有 3 个（Traffic-H192 −0.74%、H336 −0.64%、
H720 −0.31%，均为 3-seed 均值，std ≤0.008）。逐窗口归因（seed 2021–2023，
`test_window_mse.npz`，同一 checkpoint 调制开/关对比）：

- H192/H336：调制开在 90–97% 的窗口上更好；最差 1% 窗口上调制开同样更好
  （如 H192 S2021：0.876 vs 0.910）。**退化不是调制误触发**。
- H720：调制开/关几乎无差别（48–49% 窗口开更好），level 分支也基本中性；
  退化主要来自微调本身（骨干被 ×0.1 学习率移动后终点略差于起点）。
- 更深的归因（门值、q 范数与输入周期均值漂移的相关性）需要加载 checkpoint
  运行 `analyze.py` 风格的诊断，本轮未执行，列为后续可选项。

## 6. 对论文的含义（待用户决定，未改动论文）

1. 主表 PhaseFormer 行维持 Golden；LA 行维持现行从零训练结果——热启动没有
   带来可替换的收益（±1.1% 以内互有胜负），且换初始化口径需要披露，得不偿失。
2. Stage 0 的证据支持论文现有的对比叙事：在相同环境下（torch 2.6 / A800），
   会议配置 + 逐 epoch 读 test 也只在 10/28 setting 达到 Golden，因此“LA 与会议
   版的差距”应继续以协议内配对比较（重训 PF / 同协议 PF）表述，这也是金标准
   文档的既有规则。
3. 若要在论文中提及实验 1/2（可选）：热启动是“从训练好的 PhaseFormer 出发，
   扩展组件一致地改进 25/28 setting”的证据，可加强“扩展不是以精度换功能”的
   论点；代价是初始化口径不同，须披露。
