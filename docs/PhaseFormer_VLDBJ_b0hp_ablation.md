# PhaseFormer+ 组件消融（2026-11-02）

## 1. 要回答什么

PhaseFormer+（记录表里的 B0H+）在 28 个 setting 上的最佳配置已经固定。本实验在**不改动这些配置**的前提下，
逐个替换或去掉一个设计，看它值多少：

1. **仅 phase pathway**：即原版 PhaseFormer。不重跑，直接引用 `docs/PhaseFormer_gold_standard.md` 的记录值。
2. **仅 trend pathway**：融合输出换成 level 分支自己的预测（anchor + delta），phase forecast 不参与输出；
   token 输入保留，因为它是 trend 分支的输入。
3. **简单门控**：双分量门（level / shape）换成一个全局标量 α，`out = (1−α)·phase + α·trend`，
   α = sigmoid(w)，初值取该 setting 记录的 `gate_init`。
4. **linear 替换 trend 分支**：池化 → rank-3 编码 → 解码，换成一个线性层 `(B,C,720) → (B,C,H)`，
   权重零初始化；token 输入随之去掉。

## 2. 协议

- 28 个 setting 的周期、门控初值、门控/读出/backbone 学习率、head、门控共享、token 变体全部取自
  `docs/PhaseFormer_VLDBJ_b0hp_best_settings.csv`；seed 2021；E14 协议、从零训练、最多 30 epoch、按验证集早停。
- 除被替换的部件外不引入任何新超参。
- 两个例外，均与被替换部件的规模有关：
  - **linear 分支**有 720×H 个权重，远多于原分支的 105 个；配置里的读出速率最高 1000×（即 lr 1.0），
    线性层会训飞。所以只有线性层的权重改用 backbone 速率，其余参数保持原速率。
  - **仅 trend** 原配置给 level 分支的是"残差修正用"的小速率（最低 0.03×）。这一臂单独承担全部预测时，
    额外补了一组 `readout = 1.0` 的对照（`trend_only_lr1`）。
- 训练侧口径：单 seed、既定测试集选优；PhaseFormer 一列来自金标准文件，与其余各列不在同一运行环境，
  跨模型的绝对差距应按项目既有约定解读。

## 4. 读法

- **去掉 phase 后模型不可用**：仅 trend 的平均 MSE 是完整模型的两倍（0.589 / 0.572 对 0.297）。rank-3 的
  level 分支只能产生平滑的 level 轮廓，无法替代 phase 通路承担的周期形状。提高分支学习率只把
  ETTh1-720 从 1.17 修到 0.71，整体仍是 0.57。trend 通路是补充，不是替代。
- **双分量门控比单标量门控好 0.7%–3.0%**：七个数据集全部变差，平均 +1.4%。收益不大但方向一致，
  说明 level / shape 分开的门控设计有实际贡献。
- **rank-3 池化分支优于单线性层**：平均 +2.5%，七个数据集全部变差，且线性层参数量是原分支的几千倍。
  低秩瓶颈不是限制，而是有效的正则。
- 逐 setting 看，简单门控在 ETTh1-192、ETTh1-720、ETTm2-96 等与完整模型持平或几乎持平；差距集中在
  ETTh1-336（+5.4%）、Weather（+3.0%）、ETTh2-96（+5.4%）。

## 5. 限制

- 单 seed、按测试集选优，1% 级别的差别在噪声内（此前测得验证集选优相对测试最优平均损失 1.26%）。
  本实验里门控与线性分支的差距多数在 1%–5%，方向一致，但不宜解读到单个 setting 的小数点。
- PhaseFormer 列是论文金标准（不同环境与协议），不是本次协议下的配对重训；与其余列的差是"记录值对记录值"。
- `trend_only` 一臂在原配置速率下明显欠拟合（学习率是按残差用途选的），`trend_only_lr1` 是补充对照；
  两组的结论一致。
- 消融臂都从零训练并沿用原配置的周期与速率，没有为每个消融单独调参；这正是消融想回答的问题，
  但也意味着某个消融的劣势有一部分可能来自"没有自己的调参预算"。
